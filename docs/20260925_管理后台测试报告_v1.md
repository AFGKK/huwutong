## 二、P0-1 管理后台越权（核心发现）

### 现象

新注册的普通用户（无任何角色）token 访问管理后台 API：

- 采样 143 条 `api/admin/*` 无参 GET 路由，**96 条返回 200**（含 `accounting`、`security/dashboard`、`system-health/check`、`enterprise-sso/idps`、`customer-api-keys`、`sessions`、`waf/config`、`watchlist`、`tenant-isolation/dashboard` 等）
- 对照组 `api/admin/users` 正确返回 403

### 根因（源码定位）

`app/Http/Controllers/Api/AuthController.php`——登录/注册/手机号登录/重置密码全部：

```php
$token = $user->createToken('auth-token', ['*'])->plainTextToken;  // ← 通配权限
```

路由层的 `Laravel\Sanctum\Http\Middleware\CheckForAnyAbility:admin,super-admin`（797 条路由挂载）对 `['*']` token 永远放行 → **整道闸门形同虚设**。  
`AdminUserController` 之所以幸免，是因为控制器内另做了 `$this->authorize('viewAny', User::class)` Policy 校验——但绝大多数 admin 控制器没有这道二次防线。

### 修复建议（按优先级）

1. **最小修复**：`createToken` 按角色发放 abilities，如普通用户 `['customer']`、管理员 `['admin','customer']`，一行改动
2. 防御纵深：为 admin 路由组统一追加 spatie `role:super-admin` 中间件（不依赖 token abilities）
3. 回归口径：修复后以普通用户 token 重放本报告 `tests/admin_leak_forensic.py`，96 条 LEAK 应全部变 403

## 三、P0-2 订单数据隔离失效

```
GET /api/orders  (全新注册、0 订单的用户 token)
→ 200, data 含 8 条订单，样例:
  {"id":152, "order_no":"HWT20260924DUTL0TGZGL", "user_id":26443, "tenant_id":1, "status":"cancelled"}
```

`/api/orders` 路由仅挂 sanctum 认证，无用户维度过滤（与门户报告 P1-1 的 `/api/licenses/stats` 全局统计问题同源但更严重——这是明细数据泄露）。

## 四、P1-1 无能力中间件的管理路由

`api/admin/activity-feed`、`api/admin/api-gateway/config` 路由层只有 `Authenticate:sanctum`，未挂 `CheckForAnyAbility`——即使修复 P0-1 的 token 发放，这两类路由仍需补挂中间件。建议全量扫描 510+ 条 admin GET 路由的中间件覆盖情况。
