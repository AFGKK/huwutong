- **日期**: 2026-09-25
- **依据**: 四轮测试（报告 v1~v6，60+ 用例）+ 浏览器 UI 走查 + 源码定位（`D:\phpEnv\www\88.huwutong.com`）
- **总体判断**: 核心安全闭环、主链路可用，适合小范围内测；距离商用需完成第一期全部 + 第二期大部分

## 第一期 · 安全与入口加固（1~2 天，P0）

### 1.1 修改 admin 弱密码并启用 MFA

- **现状**: `admin123` 可登录 super-admin（响应含 `password_expiring: true` 但未强制）
- **改法**: 后台「账号安全」改强密码；系统已有 adaptive-security 模块，为 super-admin 角色强制开启 MFA
- **验收**: `admin123` 登录返回失败；无 MFA 无法登录后台

### 1.2 撤销遗留测试 API token

- **现状**: 历轮测试在服务端遗留多个 token（id 15040~15046 等）
- **改法**: 后台「个人令牌 / API Tokens」全部删除
- **验收**: 旧 token 调 `/api/user` 返回 401

### 1.3 修复 /admin 入口 404

- **现状**: `routes/web.php:320` 将 `/admin/{path?}` 渲染 admin SPA，但前端 Vite base=`/build/`，客户端跳 `/build/admin` → 路由 404。真实入口是 `/build/dashboard`
- **改法**（服务端 301，一处改动）:
  ```php
  Route::get('/admin/{path?}', function ($path = '') {
      return redirect('/build/' . $path, 301);
  })->where('path', '.*');
  ```
  同步处理：`/login` 的重定向目标由 `/admin/login` 改为 `/build/login`
- **风险**: 已发出的文档/书签带 `/admin/*` 链接——301 会保留 SEO 权重
- **验收**: 浏览器访问 `/admin` 落在仪表盘；登录后重定向正确

### 1.4 public-lookup 加限流

- **现状**: `POST /api/license/public-lookup` 连发 15 次全 200，无速率限制
- **改法**: `AppServiceProvider` 注册 limiter 并挂到该路由:
  ```php
  RateLimiter::for('public-lookup', fn ($r) => Limit::perMinute(30)->by($r->ip()));
  // 路由上: ->middleware('throttle:public-lookup')
  ```
- **验收**: 超限返回 429；正常查询不受影响

## 第二期 · 产品收敛（1~2 周，P1，最关键）

### 2.1 定义 MVP 边界，feature flag 隐藏空壳模块

- **现状**: 后台 100+ 菜单，其中大量与核心场景无关或只有壳（区块链 License、License 二级市场、混沌工程、蓝绿部署、AI 自动渗透测试、affiliate-enhanced…）；门户侧 4 个 API 无后端实现
- **改法**:
  1. `config/features.php` 定义 flag，默认关闭未完成模块
  2. 后台菜单组件按 flag 过滤（AdminLayout）
  3. MVP = License 生命周期 + 客户/租户 + 订单 + 查询/激活 + 计费
- **验收**: 后台无「点进去 404/空页面」的菜单；菜单数收敛到 40 以内
- **原则**: 「看起来什么都有，点什么没反应」比「功能少但每都能用」伤害信任得多

### 2.2 门户能力补齐（二选一：补齐或砍入口）

- **现状 4 个未实现端点**: `/api/subscriptions`（我的订阅）、`/api/downloads`（下载中心）、`/api/user/devices`（设备管理）、`/api/announcements`（公告列表）
- **优先级建议**: `downloads` 最优先（官网 footer 有入口迹象，是获客承接页）；`devices` 次之（激活数据已有，只差查询接口）；`subscriptions`/`announcements` 可延后
- **验收**: 每个补齐的端点纳入 pytest 用例

### 2.3 API 文档与实现对齐

- **现状**: api-docs 写 `/api/license/query`，实际是 `/api/license/public-lookup`
- **改法**: 短期手工修正文档；中期引入 scribe/l5-swagger 从路由注解生成，杜绝再次漂移
- **验收**: 文档抽查 10 个接口全部与实测一致

## 第三期 · 体验与工程（2~4 周，P2/P3）

### 3.1 后台信息架构重组

- 100+ 菜单平铺。改法：按使用频率分层——高频 8~10 项置顶 + 用户自定义收藏，其余按「License/客户/交易/系统」四大域收纳进折叠分组
- 验收：新运营同学 30 秒内找到「生成 License」

### 3.2 PWA 弹窗按场景显示

- **现状**: `AdminLayout-WvFygc71.js` 监听 `beforeinstallprompt`，非 standalone 即弹；关闭后 24h TTL 再弹，管理员也被打扰
- **改法**: 组件加路由判断——仅在 `/build/portal` 等门户路由显示；dismissed TTL 由 24h 延长到 30 天或永久
- **验收**: 后台管理页面不再出现弹窗

### 3.3 页脚神秘数字 111/333/222 ✅ 已修复（2026-09-25 验证）

- **验证**: 重新截屏授权查询页，页脚干净（产品/资源/公司三栏 + 版权 + ICP 备案号），占位数字已消失
- 截图: screenshots/08_license_query_recheck.png

### 3.4 测试体系接入 CI

- pytest 套件已交付（47 用例），CI 配置示例：
  ```yaml
  # .github/workflows/regression.yml 或 Jenkins 等价
  - run: python -m pytest tests/ -m "not write" -v   # PR 只读档
  - run (nightly): python -m pytest tests/ -v          # 每夜全量
  ```
- 补 Playwright UI 冒烟 10 条：登录→仪表盘→发 license→门户下单→查询/激活；本轮 `/admin` 404 即纯 API 测试盲区
- 验收：PR 自动跑只读回归，红阻断合并

### 3.5 错误页语义化

- 404 页增加「返回仪表盘」按钮（当前只有返回首页），管理后台内 404 不应把人踢回官网

## 实施备注（2026-09-25）

- 线上加固密码：`php artisan hwt:secure-admin --password='你的强密码'`
- 仅清理测试 token：`php artisan hwt:secure-admin --revoke-only`（可先 `--dry-run`）
- 恢复全量菜单：`.env` 设 `FEATURES_MVP_MODE=false`，前端 `VITE_MVP_MODE=false` 后重新构建
- 不纳入提交：`public/_disk_cleanup_once.php`
