## 二、发现的问题与处理状态

### P1-1｜仪表盘统计未按用户隔离（数据串号）— ✅ 已修

- **现象**: 全新用户（0 个 license）的门户仪表盘显示「全部 License 3 / 活跃 3」
- **根因**: `/api/licenses/stats` 仅按 `tenant_id` 聚合，门户用户无租户或同租户时漏看全局/他人数据
- **修复**: `LicenseController::stats` 对非管理员强制按 `customer_id` 隔离；无客户档案返回全 0。单测 `PortalLicenseStatsIsolationTest`

### P1-2｜商店页接错数据源 — ✅ 已修

- **现象**: 商店页「暂无商品」，但 `/api/shop/products` 有数据
- **根因**: 调用管理端 `/api/skus`（无库存时 total=0）
- **修复**: `shop.js` 的 `getSkus` / 页面 `searchProducts` 统一走 `/shop/products`

### P2｜工单创建 500 + SQL 泄露 — ✅ 已修

- **根因**: `tenant_id` 为 null；异常在 DEBUG 下外抛 SQL
- **修复**:
  - 回填 `tenant_id`（用户租户 → remember → 默认租户）
  - 自动 `Customer::firstOrCreate`
  - try/catch 返回友好文案，不吐 SQL
  - `bootstrap/app.php` 对 `QueryException` **永不向客户端泄露 SQL**（即使 `APP_DEBUG=true`）

### P3｜库存不足文案未翻译 — ✅ 已修

- `InventoryService` 改为 `__('app.api.common.insufficient_stock')` 等正确键

### P3｜加购 stock=0 返回误导 404 — ✅ 已修

- 库存不足 → **422 `OUT_OF_STOCK`**
- 增加兼容路由 `POST /api/cart/items` → 同 `cart/add`
- SKU 真不存在才 404

### P3｜取消订单疑似不回补库存 — ✅ 已加固

- `OrderService::cancel` 取消前 `loadMissing('items')`
- `InventoryService::rollback` 正确处理无限库存与 sold_count

### P3｜商城 SKU 全 0 库存 — ✅ 数据已补

- 代码侧支持售罄展示；演示环境已将 **3** 个 `is_active` 且 `stock=0` 的 SKU 补为 `stock=10`（当前活跃有货 3/3）
- 正式环境仍建议走后台库存管理，勿依赖一次性脚本
