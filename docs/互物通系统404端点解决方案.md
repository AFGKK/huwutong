# 互物通系统 404 端点解决方案 v1.0

> **文档状态**: ✅ 修复完成  
> **创建日期**: 2026-06-22  
> **修复日期**: 2026-06-22  
> **适用版本**: 互物通 v2.x  

---

## 1. 背景

在完成全量 API 功能测试后，发现 **13 个端点返回 404**，通过率 85.2%（75/88）。其中：

- **核心业务**：87.5%（21/24）
- **电商运营**：95.5%（21/22）
- **安全合规**：85%（17/20）
- **其余模块**：72.7%（16/22）

剩余 13 个 404 端点集中在以下两类问题：

| 类型 | 数量 | 说明 |
|:----:|:----:|------|
| **A. 后端路由缺失** | **7 组** | 控制器/Service/Model 已存在，但 `routes/api.php` 中从未注册路由 |
| **B. 前端路径不匹配** | **6 个** | 前端 API 文件调用路径与后端实际路由路径不一致 |

---

## 2. 问题分类详析

### 2.1 A 类 — 后端路由缺失（7 组）

以下 7 组功能的 **控制器、Service 层、Model 层全部已完成开发**，但路由从未注册到 `routes/api.php`，导致前端调用全部返回 404。

| # | 模块 | 控制器 | 文件状态 | 缺失路由数 |
|:-:|:----:|:-------:|:--------:|:---------:|
| A1 | License 模板管理 | `LicenseTemplateController` + `LicenseTemplateExtController` | ✅ 存在 | ~15 |
| A2 | License 快照 | `LicenseSnapshotController` | ✅ 存在 | 5 |
| A3 | License 回收站 | `LicenseTrashController` | ✅ 存在 | 6 |
| A4 | 消费预警/预算上限 | `BudgetGuardController` | ✅ 存在 | ~12 |
| A5 | 密钥泄露扫描 | `SecretScanController` | ✅ 存在 | 5 |
| A6 | 告警集成(PD/OpsGenie) | `IncidentAlertingController` | ✅ 存在 | 8 |
| A7 | 退款管理 | `RefundController` | ✅ 存在 | ~12 |

**总计缺失路由：约 63 条**

### 2.2 B 类 — 前端路径不匹配（6 个）

前端 API 文件调用路径与后端实际路由路径不一致：

| # | 前端文件 | 前端调用路径 | 后端实际路径 | 差异类型 |
|:-:|:--------:|:------------:|:------------:|:--------:|
| B1 | `alertManager.js` | `/admin/alert-manager/...` | `/alert-manager/...` | 多出 `/admin/` 前缀 (用 `apiClient`) |
| B2 | `auditGovernance.js` | `/admin/compliance/frameworks` | `/audit-governance/frameworks` | 路径完全不同 |
| B3 | `auditVisualization.js` | `/admin/audit-vis/...` | `/audit-visualization/...` | 前缀缩写不同 |
| B4 | `licenseTemplate.js` | `/admin/license-templates` | 待新增 `/license-templates` | 多出 `/admin/` 前缀 |
| B5 | `licenseSnapshot.js` | `/admin/licenses/snapshots` | 待新增 `/license-snapshots` | 路径层级不同 |
| B6 | `licenseTrash.js` | `/admin/licenses/trash` | 待新增 `/license-trash` | 路径层级不同 |

> **注**：`alertManager.js` 使用 `apiClient`（不自动 strip `/admin/`），而后端路由无 `/admin` 前缀，因此每次调用都多出 `/admin/` 导致 404。

## 3. 解决方案

### 3.1 A 类解决方案：注册缺失路由

在 `routes/api.php` 的「管理员功能路由」区域（位于 `// 以下为管理员功能路由 — 控制器已存在但之前未注册路由` 注释块内），新增 7 组路由。

#### 3.1.1 新增 use 导入

在 `routes/api.php` 头部 use 导入区追加：

```php
use App\Http\Controllers\Api\LicenseTemplateController;

use App\Http\Controllers\Api\LicenseSnapshotController;
```

### 3.2 B 类解决方案：修复前端路径

#### B1 — `alertManager.js`

**问题**：使用 `apiClient`，路径带 `/admin/` 前缀，而后端路由无 `/admin`。

**方案**：移除 `/admin/` 前缀，路径与后端 Route prefix 完全一致。

```javascript
// 修改前
dashboard() { return apiClient.get('/admin/alert-manager/dashboard'); }
// 修改后
dashboard() { return apiClient.get('/alert-manager/dashboard'); }
```

全部路径：`/admin/alert-manager/...` → `/alert-manager/...`

#### B2 — `auditGovernance.js`

**问题**：使用 `apiClient`，且路径与后端完全不同（如 `/admin/compliance/frameworks` vs `/audit-governance/frameworks`）。

**方案**：将所有路径改为匹配后端 `audit-governance` 前缀的路径。

| 前端原路径 | 后端实际路径 | 修改为 |
|:----------:|:------------:|:------:|
| `/admin/compliance/frameworks` | `/audit-governance/frameworks` | `/audit-governance/frameworks` |
| `/admin/compliance/reports` | `/audit-governance/reports` | `/audit-governance/reports` |
| `/admin/audit-tags` | `/audit-governance/tags` | `/audit-governance/tags` |
| `/admin/audit-logs/batch-tag` | `/audit-governance/audit-logs/batch-tag` | `/audit-governance/audit-logs/batch-tag` |
| `/admin/audit-logs/{id}/annotations` | `/audit-governance/audit-logs/{logId}/annotations` | `/audit-governance/audit-logs/{logId}/annotations` |
| `/admin/audit-batch-operations` | `/audit-governance/batch-operations` | `/audit-governance/batch-operations` |
| `/admin/retention-governance/dashboard` | `/audit-governance/retention-dashboard` | `/audit-governance/retention-dashboard` |
| `/admin/retention-policies` | `/audit-governance/retention-policies` | `/audit-governance/retention-policies` |
| `/admin/cleanup-schedules` | `/audit-governance/cleanup-schedules` | `/audit-governance/cleanup-schedules` |

#### B3 — `auditVisualization.js`

**问题**：使用 `apiClient`，路径前缀为 `/admin/audit-vis/`，而后端实际为 `/audit-visualization/`。

**方案**：将前缀 `audit-vis` 改为 `audit-visualization` 并移除 `/admin/`。

| 前端原路径 | 修改为 |
|:----------:|:------:|

| `/admin/audit-vis/type-distribution` | `/audit-visualization/type-distribution` |

#### B4 — `licenseTemplate.js`

**问题**：使用 `apiClient`，路径带 `/admin/` 前缀。

**方案**：移除 `/admin/` 前缀。

```javascript
// 修改前

// 修改后
export function getLicenseTemplates(params) { return apiClient.get('/license-templates', { params }) }
```

#### B5 — `licenseSnapshot.js`

**问题**：使用 `request`（自动 strip `/admin/`），路径 `/admin/licenses/snapshots` 经 strip 后变为 `/licenses/snapshots`，但后端新增路由为 `/license-snapshots`。

**方案**：改为匹配新路由路径。

```javascript
// 修改前
request({ url: '/admin/licenses/snapshots', method: 'get', params });
// 修改后（用 apiClient，避免 request 的 strip 干扰）
apiClient.get('/license-snapshots', { params });
```

> 建议将此文件改为使用 `apiClient` 统一导入。

#### B6 — `licenseTrash.js`

**问题**：同 B5，使用 `request`，路径 `/admin/licenses/trash` 经 strip 后变为 `/licenses/trash`，但后端新增路由为 `/license-trash`。

**方案**：改为匹配新路由路径。

```javascript
// 修改前
request({ url: '/admin/licenses/trash', method: 'get', params });
// 修改后（用 apiClient，避免 request 的 strip 干扰）

```

> 建议将此文件改为使用 `apiClient` 统一导入。

## 4. 实施计划

### 4.1 优先级

| 优先级 | 模块 | 工作量 | 影响范围 |
|:------:|:----:|:------:|:--------:|
| **P0** | A1-A3 License 模板/快照/回收站 | 中 | License 管理核心功能 |
| **P0** | A7 退款管理 | 中 | 财务流程 |
| **P1** | A4 消费预警/预算上限 | 中 | 客户预算管控 |
| **P1** | A5 密钥泄露扫描 | 小 | 安全合规 |
| **P1** | A6 告警集成 | 小 | 运维告警 |
| **P1** | B1-B6 前端路径修复 | 中 | 前端页面功能恢复 |
| **P2** | domain-overview/overview (B类) | 小 | 域名管理总览 |

> **注**：`domain-overview/overview` 的 404 是因为前端调用 `/admin/domain-overview/overview` 而后端路由是 `GET /domain-overview`（无 `/overview` 后缀），需要确认前端组件具体调用方式后单独修复。

### 4.2 实施步骤

```
Step 1: routes/api.php — 添加 8 个 use 导入
Step 2: routes/api.php — 添加 7 组路由（约 63 条）
Step 3: resources/js/api/alertManager.js — 移除路径中的 /admin/
Step 4: resources/js/api/auditGovernance.js — 重写全部路径
Step 5: resources/js/api/auditVisualization.js — 修复前缀
Step 6: resources/js/api/licenseTemplate.js — 移除 /admin/
Step 7: resources/js/api/licenseSnapshot.js — 改用 apiClient + 新路径
Step 8: resources/js/api/licenseTrash.js — 改用 apiClient + 新路径
Step 9: 运行 PHP lint → 前端 build → 全量测试验证
```

### 4.3 风险与注意事项

1. **控制器方法名验证**：需确认每个控制器方法名与路由中指定的一致（特别是 `LicenseTemplateExtController` 和 `RefundController` 的扩展方法）
2. **`request` vs `apiClient`**：`request.js` 自动 strip `/admin/` 会导致某些路径预期外的行为。建议新增 API 文件统一使用 `apiClient`
3. **退款路由权限**：退款管理部分路由使用 `auth:sanctum`（普通用户可用），部分使用 `ability:admin,super-admin`（仅管理员），需根据业务需求确认
4. **LicenseTemplateExtController** 的 `withExtras`、`previewGeneration`、`batchTasks`、`batchTaskDetail`、`deleteBatchTask` 方法需确认是否在控制器中已实现
5. **RefundController** 的 `riskStats`、`riskRules`、`updateRiskRule`、`storeWithRisk`、`assessRisk`、`executeDecision`、`reviewRefund` 方法需确认是否已实现
