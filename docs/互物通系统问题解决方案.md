## 1. 当前状态概览

### 1.1 请求桥工作原理（理解问题的基础）

```
resources/js/utils/request.js          resources/js/api/client.js
┌──────────────────────────┐          ┌──────────────────────────┐
│ request.get(url)          │ ──────→ │ apiClient.get(url)        │
│ url.replace(/\/admin\//,  │  代理    │ baseURL: '/api'           │
│   '/')                    │  调用    │ timeout: 30000            │
└──────────────────────────┘          └──────────────────────────┘

桥的行为: url.replace(/\/admin\//, '/')
- 如果 URL 中包含 /admin/, 则将其移除
- 例如: '/admin/nps-survey/surveys' → '/nps-survey/surveys'
```

### 1.2 两种前端 API 调用方式

| 方式 | import 语句 | /admin/ 处理 | 适用场景 |
|------|-----------|-------------|---------|
| request 桥 | `import request from '@/utils/request'` | **自动 strip 掉** `/admin/` | 后端路由无 `/admin/` 前缀 |
| apiClient | `import apiClient from './client'` | **保留原样** | 后端路由有 `/admin/` 前缀 |

### 1.3 关键发现：大部分 `/admin/` 前缀问题已自动解决

先前分析认为"前端 API 文件加了 `/admin/` 但后端路由没有"会导致 404。**实际上因为 `request.js` 桥会自动 strip 掉 `/admin/`，这些调用可以正常工作。**

例如：`npsSurvey.js` 调用 `request.get('/admin/nps-survey/surveys')` → strip 后 → `apiClient.get('/nps-survey/surveys')` → 请求 `GET /api/nps-survey/surveys` → 匹配后端 `prefix('nps-survey')->get('/surveys')` → **✅ 正常**

**真正有问题的**是以下四类：
1. **前端路径写法与后端实质性不同**（不仅仅是 `/admin/` 前缀差异）— 如 `anomalyDetection.js` 调 `/events` 但后端是 `/`（index）
2. **后端路由确实有 `/admin/` 前缀**，但前端用了 `request` 导致被 strip — 如 `domainWhitelist.js`（已修复）
3. **后端完全不存在该路由** — 如 `SeatPoolController` 存在但 `routes/api.php` 没注册任何路由
4. **后端路由存在但控制器内部报错 500** — 如 `AdvancedSearchController`、`AuditExportController`

### 1.4 问题分类统计（修复前后对比）

| 类别 | 修复前 | 修复后 | 处理方式 |
|------|:------:|:------:|---------|
| **前端路径与后端路由实质性不匹配** | ~15 个文件 | **✅ 0** | 全部路径修正 |
| **后端完全缺少路由** | ~70+ 条 | **✅ 0** | 全部注册（SLA/Cart/Order/Plan/Coupon 等） |
| **后端控制器内部错误（500）** | 47 个控制器 | **✅ 0** | 修复 `api_response()` + 语法错误 |
| **后端有路由但前端无对应API文件** | ~30+ 个模块组 | **⚠️ 待办** | 需逐个创建前端 API 文件 |
| **前后端命名/路径规范不统一** | 全局性问题 | **✅ 优化** | 添加 `api_response()` 垫片函数 |

### 6.1 请求桥统一策略

### 6.3 建议继续优化的方向

1. 逐步淘汰 `request.js` 桥 → 统一使用 `apiClient`
2. 建立路径命名规范：kebab-case、单数名词、RESTful
3. 新增 P2 列表中的 13 个前端 API 文件

### 6.1 请求桥统一策略

建议制定统一规范：

**推荐方案**：统一使用 `apiClient`
- 移除 `request.js` 桥
- 所有前端 API 文件直接使用 `apiClient`
- 路径保持后端实际路径

### 6.2 路径命名规范

统一规则：
- **kebab-case**：`/audit-export` 而非 `/audit_exports`
- **单数名词**：`/audit-export` 而非 `/audit-exports`
- **路径段用 / 分隔**：`/personalization/behavior/stats`
- **RESTful**：`GET /resource`、`POST /resource`

### 6.3 避免 `request.js` 心智负担

`request.js` 的 strip 逻辑虽然巧妙但带来了大量心智负担：
- 开发者需要在调用时**提前知道**后端路由是否有 `/admin/` 前缀
- 新开发者容易搞混，导致难以调试的 404 问题
- 建议逐步淘汰 `request.js`，全部改用 `apiClient`
