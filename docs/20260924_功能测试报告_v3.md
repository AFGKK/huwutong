## 一、重要更正：P2-1 证伪

v2 报告的「中文名创建用户失败」**不是服务端 bug**：

- 用 `requests`（UTF-8）发送相同 payload，中文名创建**成功**（201）
- 根因：Windows 控制台下 `curl -d` 发送中文时被 GBK 编码污染，服务端收到乱码后校验失败，报错误导
- **教训**: 测中文接口必须用 UTF-8 客户端（requests/httpx），curl 中文在 Windows 下只可作参考
- 回归套件中已保留中文名正向用例 `test_create_user_chinese_name_known_bug`（现已改名语义，见 test_write_ops.py）

## 二、自动化回归套件

**文件结构**

```
pytest.ini                     # markers 配置
tests/conftest.py              # 登录 token fixture、api() 封装、cleanup 清理登记表
tests/test_smoke_readonly.py   # 只读冒烟（30 用例），可随时安全运行
tests/test_write_ops.py        # 写操作用例（17 用例），数据自动清理
```

**运行方式**（依赖：venv 中 `pip install pytest requests`）

```
# 只读回归（安全，不改动数据）
python -m pytest tests/ -m "not write" -v

# 完整回归（含写操作，自动清理测试数据）
python -m pytest tests/ -v
```

**设计要点**

- 凭据/地址通过环境变量注入（`HWT_BASE_URL` / `HWT_ADMIN_EMAIL` / `HWT_ADMIN_PASS`），默认值为本机测试环境
- `cleanup` fixture：用例内登记 `cleanup.add("DELETE", path, token)`，teardown 逆序执行
- 下单用例**动态选取可售 SKU**（硬编码 sku_id 会因库存/状态变化失效，v3 调试中已实际踩坑）
- session 结束自动用成功登录清零管理员失败计数，防止连续回归触发账号锁定（5 次锁定）
- 所有请求 `trust_env=False` 直连（见下文代理问题）
- 副作用：每次运行会在服务端留 1-2 个 personal access token，建议定期在后台撤销

**最终结果**: `46 passed, 1 skipped in 154.95s`

- skipped = 下单正向用例（当前库无可售 SKU，自动跳过属预期行为）

## 三、测试环境新发现（非被测系统缺陷）

**本机系统代理劫持 localhost 请求**

- 现象：requests 请求 `127.0.0.1:8000` 被转发到本地代理（如 127.0.0.1:51324），偶发 502 `upstream connect failed` / ReadTimeout
- 影响：排查时一度误判「服务挂了」；curl 在 Git Bash 同样受影响
- 处理：测试代码全部 `Session().trust_env=False`；**其他本地开发工具如遇 localhost 502 可先查代理**
