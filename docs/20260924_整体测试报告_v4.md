## 一、P0：License 激活签名校验完全失效 — ✅ 已修复

- **验证过程**（复现 2 次）:
  1. 管理员创建 license（`POST /api/licenses`）得到真实 key
  2. 用**伪造签名**（`X-Signature: aaaa...64位`）+ 合法 UUID v4 Nonce + 当前时间戳调用 `POST /api/license/activate`
  3. 返回 `{"success":true, "message":"激活成功", "status":"active"}` —— **激活成功**
  4. **不带任何认证 token** 再次复测（另一个 license + 伪签名 `bbbb...`）→ 依然激活成功
- **影响**: 防重放机制（X-Nonce/X-Timestamp）虽然生效，但签名校验形同虚设。任何人拿到 license key 即可无限激活设备，license 授权保护被完全绕过——这是授权管理系统的核心防线。
- **根因**: `SignatureMiddleware` 在无法解析密钥（License 无 `metadata.signature_secret`）时**直接跳过校验**。
- **修复**:
  - 无密钥 → 拒绝（`SIGNATURE_KEY_UNAVAILABLE`）
  - 无显式 secret 时用系统根密钥派生 per-license HMAC 密钥，**禁止跳过**
  - 伪造签名返回 `SIGNATURE_MISMATCH`
  - 回归：`SignatureMiddlewareTest`（含真实 `/api/license/activate` 伪签名用例）

## 二、P1：两个越权问题 — ✅ 已修复

### P1-1 垂直越权：普通用户可访问 `/api/admin/tenants` — ✅

- 普通（无任何角色）用户 token 请求 `GET /api/admin/tenants` → **200**，返回**全部租户**数据
- **修复**: `TenantPolicy` + `TenantController` 全方法 `authorize`；非超管仅可见本租户；普通用户 **403**

### P1-2 水平越权 + license key 泄露：`GET /api/licenses` — ✅

- 普通用户 token 请求 → 200，返回**其他客户的 license 完整列表**，含**明文 license_key**
- **修复**:
  - 普通用户仅看本人 `customer_id` 关联的 license（无客户则空列表）
  - 非管理员响应脱敏 `HWT-****-ACEA` 形式
  - `show` 走 `LicensePolicy::view`；`export` 仅管理员

## 三、P2 问题 — ✅ 已修复

1. **`/telescope` 未登录可访问** — ✅：`Telescope::auth` 始终要求登录 + admin/super-admin（或 `telescope.view`）；`TELESCOPE_ENABLED` 默认改为 `false`
2. **普通用户 `POST /api/licenses` 返回 500** — ✅：先 `authorize('create')` → **403**；缺 `tenant_id` → **422**（不再 500）
3. **sourcemap 泄露** — ✅：生产构建 `sourcemap: false`；`public/.htaccess` 对 `*.map` 返回 403
