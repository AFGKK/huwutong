## 三、新发现问题

### P2-1 中文名创建用户失败，且报误导性错误（中） — ✅ 已修复

- **复现**: `POST /api/admin/users`，JSON body 含中文 `name`（如「测试用户中文名」）→ 422 `"The name field is required."`（name 明明已传）
- **影响**: 中文用户无法通过该接口创建，错误信息会误导排查方向
- **推测**: 姓名校验规则存在非 ASCII 兼容问题（如正则只允许 ASCII），校验失败后返回了错误的 message；或编码处理链路有问题
- **建议**: 检查 name 字段的验证规则与语言文件；form-data 传中文还报 `Malformed UTF-8`（可能与服务端编码假设有关，需一并排查）
- **修复**（2026-09-24）:
  - `AdminUserController`：姓名校验显式支持 Unicode；缺省/非法姓名返回中文明确文案
  - 修正成功文案翻译键 `app.admin_user.*` → `app.api.admin_user.*`
  - 新增 `EnsureUtf8Request` 中间件：非法 UTF-8 返回 422，避免字段静默丢失后误报「必填」
  - 回归测试：`tests/Feature/Api/AdminUserChineseNameTest.php`

### P3-3 license 允许无 customer 创建（低，待确认） — ✅ 确认为设计意图

- `customer_id=null` 创建成功（status=pending）。若业务要求 license 必须归属客户，建议后端强制校验。
- **处理**: 保留可空，支持预生成 pending 库存 Key；在 `CreateLicenseRequest` 补充说明。激活/发货链路再校验客户归属。

### P3-4 订单无 DELETE 接口（低，提示） — ✅ 已明确

- `DELETE /api/orders/{id}` 原返回「路由不支持」。若为设计意图（只允许 cancel）可忽略。
- **处理**: 增加 `DELETE` 路由，固定返回 **405** + 文案提示改用 `POST /api/orders/{id}/cancel`（订单留痕，不物理删除）。
