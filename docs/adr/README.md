# 架构决策记录 (ADR)

> **目录**: `docs/adr/` | **模板版本**: 1.0 | **对应任务**: M0-09

---

## 什么是 ADR？

架构决策记录 (Architecture Decision Record) 用于记录重要的架构决策及其上下文、后果。
每个 ADR 是一个独立文件，按编号组织，不可修改（通过新 ADR 替代旧决策）。

## ADR 编号规则

```
ADR-{序号}-{简短标题}
示例: ADR-001-laravel-tech-stack.md
```

## ADR 模板

```markdown
# ADR-{NNN}: {决策标题}

## 状态

[提议 | 已接受 | 已废弃 | 已替代]

## 日期

{YYYY-MM-DD}

## 决策者

{决策参与人员}

## 上下文

{描述需要做此决策的背景、业务需求、技术约束等}

## 备选方案

### 方案 A: {方案名称}
- **优点**: {列优点}
- **缺点**: {列缺点}
- **成本**: {实施/维护成本估算}

### 方案 B: {方案名称}
- **优点**: {列优点}
- **缺点**: {列缺点}
- **成本**: {实施/维护成本估算}

### 方案 C: {方案名称}（可选）
- **优点**: {列优点}
- **缺点**: {列缺点}
- **成本**: {实施/维护成本估算}

## 决策

{明确阐述最终选择及核心理由}

## 理由

{详细解释为什么选择此方案而非其他方案}

## 后果

### 正面
- {列正面影响}

### 负面
- {列负面影响/权衡}

### 风险
- {列出识别的风险和缓解措施}

## 合规性检查清单

- [ ] 符合 GDPR/PIPL 要求
- [ ] 符合 SOC2/ISO27001 要求
- [ ] 性能指标达标（参见具体 SLA）
- [ ] 安全审查通过
- [ ] 符合多租户隔离要求

## 相关 ADR

- {关联的 ADR 编号}
```

---

## ADR 生命周期

```
提议 → 评审 → 接受 / 拒绝
         ↓
       已接受 → 实施 → 已验证
         ↓
       需修改 → 新 ADR 替代旧 ADR
```

## 使用指南

1. **何时创建 ADR**：任何对架构有显著影响的决策
2. **何时不需要 ADR**：纯实现细节、bug 修复、微小重构
3. **ADR 位置**：`docs/adr/ADR-{NNN}-{title}.md`
4. **ADR 编号**：递增序号，避免跳号
5. **ADR 不可修改**：如需变更，创建新 ADR 替代旧 ADR
